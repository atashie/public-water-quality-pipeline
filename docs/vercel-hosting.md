# Vercel hosting for the CyAN lake dashboard, 2026-09-23

The owner wants the lake dashboard on a shareable URL for feedback on a proof of concept. The repository is not updated afterward. This note records what is deployed, the limits that apply, and the steps the owner takes in Vercel. It follows the weather repository's hosting note and the HAB dashboard, which commits its data and deploys from git.

## What is deployed

The folder `docs/dashboards/cyan-lakes/` as it is, with no build step. [vercel.json](dashboards/cyan-lakes/vercel.json) sets no framework, no install, no build, and the folder itself as the output. The page is `index.html`, so no rewrite is needed. Root Directory is a project setting in Vercel, not a property of the file.

| What | Size | In git |
|---|---|---|
| `index.html`, `vendor/`, `data/lakes.js`, the two basemaps | 8.6 MB, 7 files. What a first visit downloads before any lake is opened | Yes, since the step 1f commit |
| `data/lakes/`, the per-lake series | 72 MB, 2,321 files, 32 KB each on average | Yes, committed once on 2026-09-23 for this deployment |
| `data/pixels/`, the per-lake pixels and exact outlines | 67 MB, 2,321 files, 30 KB each on average. The outlines are 91 percent of it | Yes, committed once on 2026-09-23 for this deployment |
| Whole folder | 149 MB, 4,650 files. Largest file 4.6 MB, the Plotly library | |

The per-lake files are regenerated by `datasets/cyan/viz/build_lake_dashboard.py`. They were committed once because Vercel's git integration deploys only committed files, and because the owner does not plan to update the repository. Committing a rebuild adds about 140 MB to the history each time, since every file changes. `measured`, sizes from `du` and `stat` on 2026-09-23.

## First deployment

1. Sign in to the existing Vercel account used for the HAB dashboard and the weather report.
2. Confirm that account can see the `atashie/public-water-quality-pipeline` repository on GitHub.
3. Select **Add New → Project** and import the repository.
4. Name the project `public-water-quality-pipeline`.
5. Set **Root Directory** to `docs/dashboards/cyan-lakes` and **Framework Preset** to **Other**.
6. Keep **Install Command** and **Build Command** empty. Set **Output Directory** to `.`.
7. Confirm the production branch is `main` and deploy.
8. Open the assigned URL and run the checks below.
9. Record the account, project, source revision, URL, and the check results in a dated review.

## Verification

- Open `/`. The Map tab shows 2,321 circles, the counts, and the ranked list with its three columns.
- Open the Lake tab. The first lake's weekly plot fills, which proves the per-lake series files are served.
- On the Map tab, tick the pixels box and zoom past level 8 on a Florida lake. Squares and an exact outline appear, which proves the pixel files are served.
- Hover the squares. The readout at the bottom left names the lake and the code.
- Open a deep link such as `/#lake=166757656&tab=lake`.
- Toggle the imagery basemap at the top right of the map. Tiles stream from Esri.
- Load the page in a signed-out browser.

Only the live deployment establishes routing, access, and the URL.
